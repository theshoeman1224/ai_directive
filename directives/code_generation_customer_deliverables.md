# Code Generation for Customer Deliverables

## Status

Draft — Limitations only

This document defines the current limitations and baseline requirements for the use of AI-generated source code in customer deliverables. Additional sections, including the program-level use-case approval process, will be defined separately.

## 1. Approved AI Models

- Only approved Poolside AI models may be used to generate source code intended for customer delivery.
- The currently approved model is **Poolside Laguna XS**.
- Use of non-Poolside AI models for customer-deliverable source code is not permitted under this process.

## 2. Contract Authorization

- The applicable contract must permit general AI usage before AI-generated source code may be used for customer deliverables.

## 3. Approved Access Methods

Poolside models are currently accessible through:

- The approved Poolside VSCode extension.
- The approved Poolside CLI tool.

No other access method is currently included in this process.

## 4. Poolside CLI Automation Limitations

- Poolside CLI requires explicit user approval when the model requests access to files.
- Workflows that require Poolside to read files therefore require interactive user approval.
- Automated or unattended workflows may only be used when all required context can be supplied directly to the model without requiring Poolside to independently access files.
- If a workflow requires file access, the user must provide the required approval/input.

## 5. Program-Level Use-Case Approval

- Each team must obtain program-level approval for each specific AI code-generation use case or workflow before using that workflow for customer-deliverable source code.
- The detailed approval process, submission requirements, and approval criteria will be defined in a later section/document.
- A group of appropriate Subject Matter Experts (SMEs) will review proposed use cases.
- SME review must account for applicable contractual, engineering, and safety requirements associated with the proposed use case.

## 6. Source Code in Scope

This directive currently applies to:

- AI-generated source code intended for release or delivery to a customer.

The following are currently outside the scope of this directive:

- Build scripts.
- CI/CD configuration.
- Test code.
- Internal-only tooling.
- Customer-released documentation.

Customer-released documentation will be addressed by a separate directive.

## 7. Human Review and Engineering Accountability

- All AI-generated source code must undergo the normal code-review process required for customer-deliverable software.
- AI-generated code is subject to the same applicable engineering, testing, verification, qualification, and release requirements as human-authored code.
- Passing automated tests alone is not sufficient justification for accepting AI-generated code.
- Human reviewers remain responsible for determining whether generated code is correct and acceptable for delivery.

## 8. AI-Generated Code Tagging

The existing source-code change-number tagging convention will be extended to identify AI-generated lines.

Current convention:

```cpp
int i = 0;    //<change_number>
```

AI-generated convention:

```cpp
int i = 0;    //<change_number>-AI
```

Requirements:

- Every line of source code generated by AI must use the existing change-number tag with an `-AI` suffix.
- The `-AI` suffix provides source-level traceability for AI-generated code while remaining consistent with the program's existing line-tagging process.
- Repository-level `AGENTS.md` instructions must direct Poolside to apply the `-AI` suffix to every line of source code it generates.
- Human code reviewers are responsible for verifying that AI-generated lines are correctly tagged before the change is accepted.
- Rules governing later human modification of AI-generated lines will be defined separately.

## Deferred Topics

The following topics are intentionally deferred and will be defined separately:

- Detailed team use-case/workflow approval process.
- Required evidence and proof-of-concept material for use-case approval.
- Prompt/template requirements for approved workflows.
- Rules for modifying previously AI-generated lines.
- Safety-critical code approval criteria.
- Customer-released documentation generated or assisted by AI.
